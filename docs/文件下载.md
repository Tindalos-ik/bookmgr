## 页面操作

1. 登录系统，打开已上架图书的详情页。
2. 有附件时，页面显示文件名、格式、大小和“下载 TXT 文件”按钮；没有附件时显示“此书暂无可下载文件”。
3. 点击下载，按钮显示“正在下载…”并暂时禁用，防止重复点击。
4. 浏览器接收完整文件后触发保存，文件名使用图书附件信息中的 `name`。

当前支持 TXT 附件，读者与管理员使用相同的下载权限。新建图书没有附件，当前没有文件上传入口。

## 文件与数据库

附件保存在后端本地目录 `backend/resources/books/`。`books` 表中的字段用于关联附件：

| 数据库字段 | 用途 |
| --- | --- |
| `file_path` | 相对于资源目录的文件路径，供后端查找实际文件 |
| `file_name` | 下载时使用的文件名 |
| `file_format` | 文件格式，当前为 `TXT` |
| `file_size` | 文件字节数，供页面展示 |

图书接口公开的 `file` 包含 `name`、`format`、`size`、`url`，其中 `url` 为 `/books/{图书编号}/download`。内部 `file_path` 不对前端公开。

当前实现依据 `file_name` 是否为空生成附件信息；实际文件是否存在，会在下载请求中检查。页面显示的大小来自数据库 `file_size`，下载时读取本地文件正文。

## 下载请求

下载接口为 `GET /books/{book_id}/download`，`book_id` 是图书编号。请求通过 `Authorization: Bearer <登录令牌>` 携带身份信息。

前端 API 层根据图书编号构造下载地址，复用 `fetchResponse()` 发送请求。该函数从当前标签页的 `sessionStorage` 读取令牌，添加 `Authorization` 请求头，并设置 `cache: "no-store"`。

直接在地址栏打开下载地址时，请求不会自动携带 `sessionStorage` 中的 Bearer 令牌。页面使用 `fetch` 发起鉴权请求。

## 后端校验与响应

### 身份验证

下载路由依赖 `get_current_user()`，按以下步骤检查身份：

1. 提取 Bearer 令牌，验证 JWT 签名和有效期，读取 `sub`、`jti`。
2. 根据 `jti` 查询数据库会话，检查会话存在、用户匹配且未过期。
3. 查询用户，确认用户仍存在。

对应 [backend/dependencies.py](../backend/dependencies.py)，以下摘录省略 import：

```python
"""密码校验、JWT 签发和逐请求数据库权限检查。"""

bearer_scheme = HTTPBearer(auto_error=False)


async def get_bearer_token(
    credentials: HTTPAuthorizationCredentials | None = Depends(bearer_scheme),
) -> str:
    """提取 credentials 中的 Bearer 令牌，缺失或错误类型返回 401。"""
    if credentials is None or credentials.scheme.lower() != "bearer":
        raise HTTPException(
            401, "请提供 Bearer 登录令牌", headers={"WWW-Authenticate": "Bearer"}
        )
    return credentials.credentials


async def get_current_user(
    token: str = Depends(get_bearer_token), db: AsyncSession = Depends(get_db)
) -> UserDB:
    """验证 token 和 db 中的会话，返回当前真实用户。"""
    invalid = HTTPException(
        401, "登录已失效，请重新登录", headers={"WWW-Authenticate": "Bearer"}
    )
    try:
        payload = jwt.decode(
            token, settings.SECRET_KEY, algorithms=[settings.ALGORITHM]
        )
        user_id = int(payload["sub"])
        jti = payload["jti"]
        if not isinstance(jti, str) or "exp" not in payload:
            raise invalid
    except (JWTError, KeyError, ValueError, TypeError):
        raise invalid
    session = await db.get(AuthSessionDB, jti)
    if (
        session is None
        or session.user_id != user_id
        or session.expires_at <= datetime.now(UTC).replace(tzinfo=None)
    ):
        raise invalid
    user = await db.get(UserDB, user_id)
    if user is None:
        raise invalid
    return user
```

### 图书与文件校验

身份验证通过后，`BookService.download()` 执行文件检查：

1. 根据图书编号查询记录；图书必须存在且已上架。管理员下载同样受此条件限制。
2. 检查 `file_path` 和 `file_name` 均有值。
3. 将资源目录与 `file_path` 拼接，调用 `resolve()` 得到解析后的路径。
4. 用 `is_relative_to(RESOURCE_ROOT)` 限制文件位于资源目录内，并用 `is_file()` 确认目标是实际文件。指向目录外的路径会被拒绝。

对应 [backend/services.py](../backend/services.py)，以下摘录包含资源目录和 `BookService` 中下载所需的方法：

```python
"""图书查询、管理、收藏和受保护本地文件业务。"""

RESOURCE_ROOT = (Path(__file__).parent / "resources" / "books").resolve()


class BookService:
    @staticmethod
    async def get_book_by_id(
        db: AsyncSession, book_id: int, include_hidden: bool = False
    ) -> BookDB:
        """按 book_id 查询 db；include_hidden 仅用于内部管理。"""
        book = await db.get(BookDB, book_id)
        if book is None or (not include_hidden and not book.published):
            raise HTTPException(404, "图书不存在")
        return book

    @staticmethod
    async def download(db: AsyncSession, book_id: int):
        """校验 db 中 book_id 已上架且文件在资源目录内并存在。"""
        book = await BookService.get_book_by_id(db, book_id)
        if not book.file_path or not book.file_name:
            raise HTTPException(404, "本书暂无下载文件")
        path = (RESOURCE_ROOT / book.file_path).resolve()
        if not path.is_relative_to(RESOURCE_ROOT) or not path.is_file():
            raise HTTPException(404, "下载文件不存在")
        return path, book.file_name
```

### 下载路由

路由将校验得到的路径和文件名交给 FastAPI `FileResponse`：

- 响应正文为文件内容。
- `media_type` 设置为 `text/plain; charset=utf-8`。
- `filename` 使用数据库中的 `file_name`，由 `FileResponse` 生成附件下载的 `Content-Disposition` 响应头。
- `Cache-Control` 设置为 `no-store, private`，要求缓存端不保存响应。

对应 [backend/routers/book.py](../backend/routers/book.py)，`router` 的前缀为 `/books`：

```python
"""图书列表、管理和鉴权文件下载路由。"""

@router.get("/{book_id}/download", summary="下载已上架图书的 TXT 文件")
async def download(
    book_id: int,
    db: AsyncSession = Depends(get_db),
    user: UserDB = Depends(get_current_user),
):
    """为已登录 user 下载 db 中 book_id 的受保护 TXT。"""
    path, filename = await BookService.download(db, book_id)
    return FileResponse(
        path,
        media_type="text/plain; charset=utf-8",
        filename=filename,
        headers={"Cache-Control": "no-store, private"},
    )
```

### 文件读取与字节发送

路由返回 `FileResponse` 响应对象后，FastAPI 会调用它的 ASGI 接口 `__call__()`，开始发送响应。传入的 `path` 是服务器内部的文件定位参数，浏览器接收的是 HTTP 响应正文中的文件字节。

FastAPI 使用 Starlette 提供的 `FileResponse`。在普通整文件 GET 请求的分块读取分支中，`FileResponse._handle_simple()` 负责读取文件并调用 ASGI 的 `send()`。下面摘录该分支的主体：

```python
"""FileResponse 普通文件响应的分块读取与 ASGI 发送片段。"""

async with self._open_file() as file:
    more_body = True
    while more_body:
        chunk = await file.read(self.chunk_size)
        more_body = len(chunk) == self.chunk_size
        await send({"type": "http.response.body", "body": chunk, "more_body": more_body})
```

- `_open_file()` 内部通过 `anyio.open_file(self.path, mode="rb")` 以二进制模式打开文件，并在退出时关闭文件。
- 当前安装版本的 `chunk_size` 为 `64 * 1024`，每次最多读取 **64 KiB**。文件分块读取，后端无须先将完整文件读入内存。
- `body` 是本次读取的字节；`more_body=True` 表示响应尚未结束，`False` 表示响应正文结束。
- `send()` 是 ASGI 服务器提供的异步接口。`await send(...)` 将这一块数据交给服务器处理。

源码位于后端安装环境的 `starlette/responses.py`。该类还处理 HEAD、Range 请求，以及服务器支持 `http.response.pathsend` 扩展时交由服务器读取文件的分支；上面的代码展示默认分块读取路径。

### HTTP 网络传输

项目使用 Uvicorn 运行 FastAPI。Uvicorn 接收 `http.response.start` 消息处理状态码和响应头，接收 `http.response.body` 消息处理文件字节，再通过网络连接发送给浏览器。

以 Uvicorn 的 h11 HTTP 实现为例，其 `send()` 方法处理响应正文的关键语句如下：

```python
"""Uvicorn h11 实现中响应正文的 HTTP 编码与网络写入片段。"""

body = message.get("body", b"")
more_body = message.get("more_body", False)

data = b"" if self.scope["method"] == "HEAD" else body
output = self.conn.send(event=h11.Data(data=data))
self.transport.write(output)
```

`h11.Data` 将正文交给 HTTP 协议实现编码，`transport.write()` 将编码后的数据提交给网络传输层，后续由操作系统发送。这里使用的协议实现源码位于后端安装环境的 `uvicorn/protocols/http/h11_impl.py`；Uvicorn 选择其他 HTTP 实现时，具体编码代码会不同。

文件读取的分块大小与实际网络数据包大小分别由应用读取逻辑和网络协议栈决定，64 KiB 的文件块可以在网络传输时继续拆分。

## 前端接收与保存

详情页的 `downloadBook()` 按以下顺序执行：

1. 保存本次点击对应的图书及附件信息，设置下载中状态并清空上次错误。
2. 调用 store 的 `downloadFile()`，再由 API 层请求下载接口。
3. 浏览器在网络传输过程中接收响应正文；`response.blob()` 等待整个正文接收完毕后返回 `Blob`。
4. 调用 `URL.createObjectURL(blob)` 创建临时对象地址。
5. 创建 `<a>` 元素，将 `href` 设为对象地址，`download` 设为附件信息中的 `file.name`；插入页面并调用 `click()` 触发浏览器保存。
6. 移除 `<a>` 元素，延迟 1 秒调用 `URL.revokeObjectURL()` 释放对象地址。
7. 显示“已开始下载”，并在 `finally` 中解除下载中状态。

`Blob` 表示已经接收的文件数据，对象地址供浏览器访问这份数据。前端保存文件时使用图书接口提供的文件名，没有解析下载响应中的 `Content-Disposition`。

当前前端需要完整接收文件后才触发保存，大文件会带来较大的浏览器内存开销。“已开始下载”表示已触发浏览器保存动作，页面无法据此确认用户是否保存完成。

## 错误处理

| 情况 | HTTP 状态码 | 后端消息 |
| --- | --- | --- |
| 缺少 Bearer 令牌或认证类型错误 | `401` | 请提供 Bearer 登录令牌 |
| JWT 无效、过期，会话失效或用户不存在 | `401` | 登录已失效，请重新登录 |
| 图书不存在或已下架 | `404` | 图书不存在 |
| 缺少附件路径或文件名 | `404` | 本书暂无下载文件 |
| 路径超出资源目录，或目标文件不存在 | `404` | 下载文件不存在 |

预期 HTTP 错误由后端统一转换为包含 `code`、`msg`、`data` 的 JSON 响应。前端对失败响应读取错误消息，对成功响应读取 `Blob`。

store 收到 `401` 后清理失效会话。API 层和 store 使用请求所属的会话代次检查结果；切换会话后，旧请求的结果会被丢弃，详情页忽略这类取消错误。

连接失败、接收文件时连接中断以及后端返回的错误，会显示在下载按钮下方。错误处理结束后按钮恢复可点击，用户可再次尝试。
